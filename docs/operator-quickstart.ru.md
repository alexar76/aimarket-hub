# Свой собственный хаб

[English](operator-quickstart.md) · [Русский](operator-quickstart.ru.md) · [Español](operator-quickstart.es.md) · [Français](operator-quickstart.fr.md) · [中文](operator-quickstart.zh.md)

> Терминология соответствует каноническому [глоссарию локализации](https://github.com/alexar76/aicom/blob/main/docs/localization-glossary.md). Названия продуктов, идентификаторы протокола, URL, CLI-команды и переменные окружения не переводятся.

Вы его склонировали и развернули, и честный вопрос — что вам это даёт. Эта страница — кратчайший
путь от свежего развёртывания до хаба, который действительно может брать деньги: без блокчейна,
без контракта, без кошелька, без аккаунта у кого бы то ни было.

## Три минуты

```bash
pip install "aimarket-hub[pqc]"        # [pqc]: постквантовые подписи (см. ниже)
export AIMARKET_CREDITS_ENABLED=1      # платёжный канал
export AIMARKET_ORACLE_FAMILY_URL=off  # оценивайте издателей сами (см. ниже)
export AIMARKET_PQC=1                  # гибридная подпись: Ed25519 + ML-DSA-65
python -m aimarket_hub quickstart
python -m aimarket_hub serve
```

`quickstart` делает три вещи, которых свежий хаб сам сделать не может:

1. **Публикует capability, которая действительно ваша и действительно исполняется.** Иначе
   свежий каталог либо пуст, либо состоит из чужих пиров. Образец — *статический пакет*:
   JSON-объект в `prompt_template`, который обработчик вызова возвращает как есть, поэтому ему
   не нужны ни поставщик, ни модель, ни сеть. Замените его своим сервисом, указав `invoke_url`,
   или отредактируйте пакет.
2. **Выпускает ключ покупателя** с небольшим стартовым балансом, чтобы вы могли провести
   продажу на своём хабе, прежде чем показывать его кому-либо.
3. **Печатает две команды curl**, которые эту продажу проводят.

Ещё он говорит, как хаб будет подписывать и где лежат его ключи.

## Постквантовые подписи с первого запуска

Две строки про PQC выше делают разное:

- **`[pqc]` нужен, чтобы хаб видел пиров.** Он ставит проверку ML-DSA-65. Проверка
  постквантовой подписи отказывает закрыто, поэтому хаб без неё никогда не проиндексирует пира,
  который подписывает гибридно, — а все хабы AIMarket подписывают именно так.
- **`AIMARKET_PQC=1` включает гибридную подпись.** Манифест, discovery-документ и квитанции
  хаба несут подпись ML-DSA-65 рядом с Ed25519, а пиры закрепляют ваш постквантовый ключ, как
  только впервые его увидят.

Постквантовый ключ — второй файл рядом с классическим: `<AIMARKET_SIGNING_KEY_PATH>_mldsa`,
по умолчанию `data/hub_signing_key_mldsa`. Бэкапьте оба вместе и держите их на одном томе.
Потеряете файл ML-DSA — и каждый пир, который его закрепил, будет отвергать ваш хаб, пока не
перепривяжет ключ (`POST /federation/peers/repin`). Подробнее:
[постквантовая миграция](https://github.com/alexar76/aicom/blob/main/docs/pqc-migration.ru.md).

## Как вам платят

Платёжных каналов два, можно включить любой или оба.

| | Кредиты (`X-API-Key`) | Каналы (`X-Payment-Channel`) |
|---|---|---|
| Настройка | одна переменная окружения | контракт эскроу, который вы разворачиваете на Base, + 5 предварительных настроек |
| Минимальная списываемая сумма | $0.00001 | $0.01 (целые центы, с округлением вверх) |
| У кого деньги | у вас, предоплата | у вас, предоплата (ончейн-депозит) |
| Что нужно покупателю | HTTP-клиент | пополненный кошелёк и подпись typed data |

**Кредиты** — канал, который работает при `AIFACTORY_CRYPTO_ENABLED=0`, а это значение по
умолчанию. После включения цена в листинге означает деньги: платная capability отвечает `402`
со списком принимаемых способов оплаты, а вызов с действующим `X-API-Key` резервирует цену до
запуска поставщика, списывает её при успехе и возвращает при любой ошибке.

```
POST /ai-market/v2/accounts                    # покупатель выпускает ключ (с ограничением частоты)
GET  /ai-market/v2/account                     # баланс покупателя
GET  /ai-market/v2/account/ledger              # каждое движение его собственных денег
POST /ai-market/v2/accounts/{id}/credit        # вы пополняете его  (admin bearer)
POST /ai-market/v2/accounts/{id}/status        # вы отключаете его  (admin bearer)
GET  /ai-market/v2/stats/live                  # summary.credits — заработано и должно
```

Деньги входят только через `/credit`, и этот маршрут — только ваш. Чем бы вам ни платили —
счётом, оплатой на сайте, переводом стейблкоина, который вы видели в сети, — вы вызываете
`/credit`, когда деньги уже у вас. Хаб не делает вид, что что-то собрал.

### Что вы на себя берёте

Предоплаченный баланс — это деньги вашего клиента в вашем реестре. Ровно поэтому `stats/live`
публикует `outstanding_credit_usd` рядом с `credits_earned_usd`: первое — обязательство,
второе — выручка, и хаб, который их не различает, рано или поздно тратит одно, думая, что это
другое. Хаб ничего не умеет отправлять, поэтому возвраты делаете вы.

### Настройки

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `AIMARKET_CREDITS_ENABLED` | `0` | сам платёжный канал |
| `AIMARKET_CREDITS_OPEN_SIGNUP` | `1` | может ли незнакомец сам выпустить себе ключ |
| `AIMARKET_CREDITS_FREE_GRANT_USD` | `0.05` | стартовый баланс самостоятельно выпущенного ключа |
| `AIMARKET_CREDITS_SIGNUPS_PER_HOUR` | `5` | лимит самостоятельных регистраций на один адрес |
| `AIMARKET_ECOSYSTEM_FILE` | `ecosystem.json` рядом с базой | какие аккаунты, серверы и кошельки — ваша собственная экосистема: их вызовы — SELF, а не внешний спрос; см. [классы трафика](traffic-classes.ru.md) |
| `AIMARKET_OPERATOR_ACCOUNTS` | пусто | старый короткий способ задать `self.accounts` из этого файла (id аккаунтов через запятую); сливается с ним |
| `AIMARKET_ROUTING_FEE_BPS` | `100` | ваша доля, когда вы перепродаёте capability другого хаба |
| `AIMARKET_PQC` | не задан = авто | не задан: новый хаб подписывает гибридно (Ed25519 + ML-DSA-65), хаб с ключом ML-DSA продолжает им подписывать, хаб только с Ed25519 таким и остаётся; `1` / `0` задают явно |

## Как дать другим публиковаться на вашем хабе

Кредитный аккаунт — это личность, а не только кошелёк, поэтому через него же кто-то публикует
у вас capability: без правки `.env`, без перезапуска, без блокчейна.

```bash
curl -X POST $HUB/ai-market/v2/accounts                      # они получают ключ
curl -X POST $HUB/ai-market/v2/accounts/<id>/credit \
     -H "Authorization: Bearer $ADMIN" -d '{"amount_usd": 30}'   # вы принимаете их деньги
curl -X POST $HUB/ai-market/v2/supply/stake \
     -H "X-API-Key: <key>" -d '{"amount_usd": 25}'               # они вносят залог
curl -X POST $HUB/ai-market/v2/supply/register \
     -H "X-API-Key: <key>" -d @manifest.json                     # они публикуют
```

Ключ говорит ровно за одного издателя — за свой собственный аккаунт. Он не может внести залог
за другого или опубликовать от чужого имени, чего общий токен публикации никогда не мог
предотвратить.

Залог — настоящее списание с их баланса, то есть деньги, которые вы держите и можете изъять
слэшингом. Он записывается как отдельный вид обеспечения, не путается с dev-заглушкой и
проходит продакшен-проверку залога. Ончейн-путь по-прежнему есть и по-прежнему требует
проверенного `tx_hash`, но хаб, в образе которого нет проверки депозитов, больше не вынужден
выбирать между «без обеспечения» и «непроходимой проверкой».

Доверие к издателям: при `AIMARKET_ORACLE_FAMILY_URL=off` спрашивать некого, поэтому издатели
получают задокументированную нейтральную стартовую оценку, а проверка доверия не применяется.
Направьте переменную на свой экземпляр LUMEN, если вам нужна оценка.

## Как платить вашим продавцам

Если у издателя capability есть здесь кредитный аккаунт, каждая завершённая продажа делится
автоматически: `AIMARKET_PUBLISHER_SHARE_BPS` (по умолчанию 70%) зачисляется ему, остальное —
вам. Раньше у хаба не было пути выплат продавцам: реестр каналов не умеет отправлять деньги, а
единственная таблица обязательств возвращает деньги вкладчикам, а не поставщикам. Продавец мог
опубликоваться, получить вызов — и всё равно просить вас вручную перевести ему десятую долю
цента.

`stats/live` показывает раздел честно: `credits_earned_usd` — это валовая сумма (сколько
потратили покупатели), `publisher_payouts_usd` — сколько ушло продавцам, `operator_net_usd` —
сколько осталось у вас. Неудачный вызов не оплачивается никому: выплата идёт тем же списанием,
что и оплата покупателя.

## Перепродажа других хабов

Когда вы направляете вызов пиру, за которого не продавали сами, комиссия за маршрутизацию
**резервируется до того, как пира о чём-либо попросят**, — в том платёжном канале, которым
пользуется покупатель. Вызывающий без оплаты получает `402` с суммой комиссии; отказ пира ничего
не стоит покупателю; пир, который берёт меньше опубликованной цены, оплачивается по меньшей
сумме. Если не хотите брать за перепродажу, поставьте `AIMARKET_ROUTING_FEE_BPS=0` — это и есть
отказ, а не пропущенный заголовок.

Канал на эскроу не может авторизовать комиссию за маршрутизацию (подписанной авторизации на неё
нет), поэтому такое сочетание отклоняется, а не записывается выручкой, которую вы никогда не
смогли бы получить. Покупателям на этом пути нужен кредитный аккаунт.

### Перепродажа платного пира

Перепродажа двигает деньги, только если вы можете заплатить другой стороне. Заведите кредитный
аккаунт у пира и укажите его:

```bash
export AIMARKET_PEER_API_KEYS="https://peer.example=aimk_your_key_there"
```

Теперь маршрутизированный вызов к этому пиру — перепродажа: с вашего покупателя списывается цена
из каталога плюс ваша комиссия, вы платите пиру со своего аккаунта у него, а комиссия — ваша
наценка. Без ключа `402` пира доходит до покупателя, у которого там нет аккаунта и который
ничего не может с ним сделать. Поэтому в живой федерации до сих пор были только бесплатные пиры.

Хабы-пиры вызываются через их `/ai-market/v2/invoke`, а не через `mcp_endpoint`: тот говорит на
MCP JSON-RPC поверх SSE и на маршрутизированный конверт отвечает `Method not found` внутри тела
`text/event-stream`. Пока это не исправили, маршрутизация между хабами была невозможна.

## Приём платежей x402

Продажа из каталога идёт напрямую продавцу. Ответ 402 называет `payout_address` листинга и
`nonce` счёта, и только в его JSON-теле есть `payment_secret`, где
`nonce = sha256(payment_secret)`. Покупатель платит на этот кошелёк ончейн через EIP-3009
`transferWithAuthorization`, подписанный на этот nonce, и повторяет запрос с
`X-Payment: <tx hash>` (или `PAYMENT-SIGNATURE`), `X-Payment-Nonce` и `X-Payment-Secret`.
Секрет доказывает, что платил именно этот покупатель: транзакция и её nonce становятся
публичными, как только попадают в блок. Хаб проверяет перевод и никогда не держит деньги
(`aimarket_hub/settle.py`): засчитывается только перевод, который сделала эта авторизация, и
каждая авторизация — отдельное требование, так что две авторизации в одной транзакции покупают
два вызова. При федеративном вызове платёж идёт рядом с вашим ключом пира, только если хаб
провёл его расчёт на этом же запросе, — с собственным nonce и с сохранённым секретом. Хаб без
ключа к этому пиру, который ничего не рассчитывал, — это ретранслятор: он передаёт платёжные
заголовки покупателя дальше, включая секрет. Каждый платёж привязан (простой перевод продавцу
отклоняется; `AIMARKET_SETTLE_REQUIRE_BINDING=0` игнорируется), поэтому клиенты покупателей,
написанные под прежний хаб и отправлявшие только `X-Payment` и `X-Payment-Nonce`, отклоняются,
пока не начнут отправлять и секрет. MCP-шлюз принимает его как `x_payment_secret`, а мост A2A
передаёт его сам. Миграция `040` добавляет колонку счёта, где он хранится, а
`X-Payment-Secret` есть в списке разрешённых заголовков CORS, так что браузерный клиент с
источника из `AIMARKET_CORS_ORIGINS` тоже может оплатить. `AIMARKET_X402_ACCEPT=0` оставляет
режим только обнаружения.

Кредиты и платёжные каналы остаются удобством для предоплаты. Издателю с кошельком платят не
через них.

## Как незнакомцам вас найти

Всегда открыты две двери для наблюдения, и обе ведут в карантин, а не к немедленному доверию:
неаутентифицированный `POST /federation/announce` и встречное обнаружение, когда пир обходит
вас и называет себя. В обоих случаях пир попадает в состояние `pending` с `trusted=false`. Затем
автоматически запускается проверка в песочнице; результат `pass` индексирует пира без нажатия
Approve. Fail и review остаются в ожидании решения в `/operator`. Отдельная таблица
предпросмотра хранит то, что предлагает ожидающий пир; эти строки никогда не попадают в поиск
или маршрутизацию, потому что их вообще нет в таблице `capabilities`. См.
`docs/join-the-federation.md`.

## Самостоятельность

Два значения по умолчанию указывают на эталонное развёртывание, и вам, скорее всего, не нужно
ни то, ни другое:

- **Доверие к издателям.** `AIMARKET_ORACLE_FAMILY_URL` по умолчанию указывает на экземпляр
  LUMEN другого оператора. Оставите так — и ваша возможность публиковать будет зависеть от его
  доступности: capability, опубликованная, пока он недоступен, сохраняется без оценки, и каждый
  её вызов отвечает 502. `off` означает, что у хаба нет оракула доверия: издатели получают
  задокументированную нейтральную стартовую оценку, и проверка не применяется. Если у вас есть
  свой экземпляр, укажите его.
- **Сиды федерации.** Поставляемый список сидов — это собственные сателлиты эталонного хаба. Это
  каталог для просмотра, а не ваше предложение; см. `AIMARKET_SEED_LIST`.

## Название

Код распространяется под Apache-2.0 (в остальной экосистеме — MIT), и вы можете использовать его
коммерчески, назначать свои комиссии и оставлять их себе целиком; никакая доля никуда не
уходит. Лицензии на товарный знак нет, поэтому не называйте своё развёртывание «AIMarket» и не
намекайте на одобрение. «Implements the AIMarket Protocol» и «interoperates with <peer>» —
точные и допустимые формулировки. Никто не может заявлять «certified» или «conformant»: набора
тестов на соответствие пока нет.
